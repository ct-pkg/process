## 2 待办一：包身份与依赖声明写全

- **为什么需要**：本包将来要被别的包依赖，也要能在本地 store 里与同名包区分。现在 `ct.pkg` 只有 `name`，缺发布者与命名空间根；依赖写法也只有短名。这样别人无法准确定位本包，本包自己声明依赖时也缺少统一写法。
- **要做什么**：在 `ct.pkg` 中补 `publisher` 与 `ns-root`；包间依赖统一写成 `<publisher>/<name>@<range>` 全名。
- **事实核对**：包管理器侧能力已核实就绪——包按发布方/包名/版本落盘，`publisher` 与 `ns-root` 为必填，`ns-root` 参与头文件搜索根展开，lock 记录发布方与单元根，构建默认读 lock 并自动补搜索根，索引含六字段。工作区未提交的 `ct.pkg` 已出现 `publisher = ct`、`ns-root = .`，但未提交，不计为完成。
- **真实阻塞**：①`ct.pkg` 未提交改动的提交范围未定，需 owner 处置；②本仓未立项，没有 phase 卡承接验收；③当前没有包间依赖，全名写法只能在第一条依赖出现时被真正验证。
- **可否立即开工**：可以。只读核对（字段是否存在、编译搜索根是否包含 `ns-root`）现在就能做；改文件要等 owner 对未提交改动给出处置。
- **先做什么**：owner 确认 `publisher` 取值与未提交改动的提交范围 → 逐条跑下面验收 1、3、4、5 → 出现包间依赖时补跑验收 2。
- **验收方式**：
  1. `ct.pkg` 同时含 `publisher` 与 `ns-root`，值非空；
  2. 包间依赖全部为全名写法，仓库内检索不到短名写法（当前无依赖，本条按空集成立；第一条依赖出现时必须满足）；
  3. 干净目录下按全名 `ct get` 与 `ct install` 均退出 0；
  4. 实际编译命令的头文件搜索路径包含 `ns-root` 所指目录；
  5. 负例：`publisher` 缺失或 `ns-root` 指向不存在的目录时，命令非零退出并打印具体原因。
