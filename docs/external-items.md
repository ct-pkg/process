## 2 条目详情

### 2.1 EXT-PROC-01

- **来源编号**：EXT-PROC-01（原在 CT 仓提案 §10 S4）。
- **要做什么**：在包元数据里补 `publisher` 与 `ns-root`；包间依赖声明统一写成全名 `<publisher>/<name>@<range>`，不再使用短名。
- **前置能力**：C1 —— `ct get` 能把包落进 store 并读取 `publisher`；C2 —— `ns-root` 进入 `-I` 搜索路径。两者均未落地（见 §3）。
- **验收方式**（前置满足后逐条执行）：
  1. `ct.pkg` 同时含 `publisher` 与 `ns-root`，值非空，`grep` 可逐个命中；
  2. 包间依赖行全部形如 `<publisher>/<name>@<range>`，全仓检索不到旧短名写法；
  3. 干净目录下 `ct get <publisher>/<name>@<range>` 与 `ct install` 均退出 0；
  4. 编译命令的 `-I` 列表包含 `ns-root` 所指目录（以实际生成的编译命令或构建日志为准）；
  5. 负例：`publisher` 缺失或 `ns-root` 指向不存在目录时，`ct get` / `ct build` 非零退出并打印具体原因。
- **当前状态**：未提交的工作区 `ct.pkg` 已出现 `publisher = ct`、`ns-root = .` 两行（其他会话的在途改动，非本次登记所写，见 §4 P-01）；`requires` 仍是编译器下限；本包目前没有包间依赖条目，因此「依赖改全名」在出现第一条包间依赖时适用。能力前置未满足前不再推进本条。

### 2.2 EXT-PROC-02

- **来源编号**：EXT-PROC-02（原在 CT 仓提案 §10 S4）。
- **要做什么**：二选一 —— ①明确登记为「规格占位」（只承诺规格，不承诺公开单元），或 ②补齐公开单元。仅走规格占位者登记 dormant，不打 tag。
- **前置能力**：C1、C2（同 EXT-PROC-01，见 §3）。
- **验收方式**：
  - 若走规格占位：①本文件与 `docs/requirements.md` 明确写出「规格占位」及未实现范围；②`ct.pkg` 不宣称已实现任何公开单元；③仓库无 tag；④README 状态保持「未立项」。
  - 若改判补公开单元：①公开单元可被 `ct install` 后导入并通过其自带用例；②`ct.pkg` 的单元清单与实际文件一致；③上述 ①② 的占位表述同步撤销。
- **当前状态**：取规格占位。依据：本仓无实现、无 phase 卡，README 明载「需求层梳理完成，未立项」。未打 tag。若后续立项并补公开单元，本条改走补单元路径并重写验收。
